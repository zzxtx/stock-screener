# 沪深主板「涨停 + 跳空缺口 + 筹码收敛」选股器

从零重写的独立项目（与 `股票筛选2`、`股票筛选3` 无代码依赖）。
按「涨停后仍留着向上跳空缺口、且筹码在收敛」这一组形态，从沪深主板全市场筛选个股。

> 数据源：新浪财经公开行情接口。本项目只做数据筛选，**不构成任何投资建议**。

---

## 一、筛选条件

| # | 条件 | 判定口径 |
|---|------|----------|
| 0 | 市场 | 沪深主板 —— 沪市 `600/601/603/605`，深市 `000/001/002`；剔除 ST、\*ST、退 |
| 1 | 股价 | 3 元 < 收盘价 < 25 元（严格不含边界） |
| 2 | 涨停 | 涨停日 T **恰好是 2 个交易日前**，且**非连板**（T-1 日不是涨停） |
| 3 | 缺口 | T+1 跳空，且到今天为止**缺口上方（含缺口当根）只有 2 根 K 线**、未回补 |
| 4 | 筹码 | 当日筹码集中度 **小于** 上一日（筹码在收敛） |

四条全部满足才算命中。

### 这是一条「定时」信号，不是区间筛选

四条条件把时间点钉死在**涨停后的第 2 个交易日**，对应一套完整的交易节奏：

| 交易日 | 发生什么 | 动作 |
|--------|----------|------|
| T | 涨停（此前不是涨停） | — |
| T+1 | 向上跳空，缺口形成 | 观察，不动 |
| **T+2** | 缺口上方累计第 2 根 K 线 | **收盘后跑本程序，今日进场** |
| T+3 | 缺口上方第 3 根 K 线 | **找机会离场** |

所以程序只会在「缺口上方刚好 2 根 K 线」这一天给出信号 ——
晚一天（3 根）就不再命中，这正是 `BARS_ABOVE_GAP = 2` 的含义。

### 口径细节

**涨停**：主板 10% 口径，按「收盘涨幅 ≥ 9.8%」近似判定，未区分一字板与烂板。
涨停日不靠搜索，而是被缺口位置反推出来（缺口在倒数第 2 根，涨停就是它前一根），
因此涨停必然恰好发生在 2 个交易日前。

**非连板**：涨停日 T 的前一交易日 T-1 若也是涨停，则视为连板，剔除。

**向上跳空缺口**：当日最低价 > 前一日最高价，缺口区间 = `[前一日最高价, 当日最低价]`。

**未回补**：缺口出现之后所有 K 线的最低价都没进入该区间。
即便只是盘中刺到缺口上沿也算已回补 —— 最严格的口径。
把 `GAP_ALLOW_PARTIAL` 设为 `True` 可放宽为「允许部分回补」。

**缺口位置**：`BARS_ABOVE_GAP = 2` 一个参数同时锁死两件事 ——
缺口落在倒数第 2 根 K 线，涨停落在倒数第 3 根。
跳空涨停（缺口在 T 当天）、第三日才跳空（T+2）、以及缺口上方已经累积了 3 根以上 K 线的，
统统不算。另外要求缺口幅度 ≥ 0.2%（`GAP_MIN_PCT`），过滤掉不足 1 分钱的伪缺口。

**筹码集中度**（这个是本项目唯一需要建模的部分）：

```
集中度 = (P95 − P5) / (P95 + P5) × 100
```

P5 / P95 是筹码分布累计 5% 和 95% 分位对应的价格，**数值越小表示筹码越集中**。
条件要求「今日 < 昨日」，即筹码在收敛。

筹码分布本身用经典的三角形分布 + 换手衰减模型估算：

- 价格轴按最近 90 个交易日的价格区间均分为 120 档；
- 每日旧筹码按 `1 − 换手率` 衰减；
- 当日换手部分按三角形分布铺在 `[最低价, 最高价]` 上，峰在均价位置；
- 累计后取 5% / 95% 分位，**分位数在档内做线性插值**。

> 为什么要插值：价格区间被分成 120 档时每档约 0.15 元，若直接把分位数吸附到档中心，
> 连续几天的 P5/P95 会完全相同，集中度永远不变、条件永远不成立。
> 这是本项目开发中实际踩到的坑，`selftest.py` 里有对应回归用例。

这套算法是**近似**，与同花顺 / 通达信的 CYQ 不保证逐位一致，但方向性一致：
分布越宽，集中度越大；横盘越久，集中度越小。

## 二、实测效果

信号只在一个时间点成立，所以命中数**逐日波动很大** —— 有些天 9 只，有些天 0 只，
这本身就是「定时信号」的正常表现，不是程序不稳定。

| 基准日 | 候选 | 股价 | 涨停恰在 2 日前 | 缺口上方 2 根 | 筹码收敛 | 命中 |
|--------|------|------|-----------------|---------------|----------|------|
| 2026-11-03 | 3010 | 2376 | 25 | 5 | 1 | **1** |
| 2026-11-04 | 3010 | 2363 | 76 | 11 | 9 | **9** |
| 2026-11-05 | 3010 | 2358 | 29 | 0 | 0 | **0** |

11-04 的完整漏斗：

```
------------------------------------------------------------
筛选漏斗（候选 3010 只，可计算 2997 只）
------------------------------------------------------------
  [OK] 3 元 < 股价 < 25 元          2363 只  78.8%  ####################.....
  [OK] 涨停恰在 2 个交易日前               76 只   2.5%  #........................
  [OK] 缺口上方仅 2 根 K 线               11 只   0.4%  .........................
  [OK] 筹码集中度小于上一日                  9 只   0.3%  .........................
------------------------------------------------------------
  四条全部满足：9 只
```

命中样例（2026-11-04，全部是「11-02 涨停 → 11-03 跳空 → 11-04 进场」）：

```
603598 引力传媒  收19.69 涨+10.00% | 缺口 11-03(+0.35%) | 集中度 13.23 → 12.96
605577 龙版传媒  收15.73 涨+10.00% | 缺口 11-03(+10.00%) | 集中度 22.05 → 21.72
002811 郑中设计  收20.37 涨 +9.99% | 缺口 11-03(+2.86%) | 集中度 26.25 → 25.05
000156 华数传媒  收 7.70 涨 +3.36% | 缺口 11-03(+1.79%) | 集中度  9.56 →  9.46
600570 恒生电子  收21.56 涨 +1.84% | 缺口 11-03(+0.63%) | 集中度  8.73 →  8.65
```

> 11-05 那天 29 只涨停股，次日（11-04）没有一只走出「全天不碰前一日最高价」的真跳空，
> 所以缺口这一关直接归零。抽样核对过其中 4 只，次日最低价都跌到了前高之下，
> 属于市场本身的走势，不是判定过严。

**为什么不用连板涨停的那批票？** 因为条件 2 要求「非连板」，
而连板股在 T+1 通常直接封死，反而没有可用缺口 —— 这也是这套条件筛出来的
多为「一根涨停 + 次日跳空 + 横盘两天」的形态。

## 四、用法

**环境**：Python 3.8+，无需安装任何第三方库。

```bash
cd pc
python screen.py                    # 交互式输入日期，回车=最近交易日
python screen.py 2026-11-05         # 指定基准日
python screen.py --limit 200        # 只算前 200 只，调试用
python screen.py --workers 8        # 提高并发
```

一个交易日全量约 **160 秒**（3010 只候选，6 线程；比纯价格类筛选慢，
主要开销在每只股票 90 天的筹码分布迭代）。

**输出**：`output/命中_<基准日>_<时间戳>.csv`，UTF-8 BOM，Excel 双击不乱码。

| 字段 | 说明 |
|------|------|
| 代码 / 名称 / 基准日期 / 收盘价 / 当日涨幅% / 流通市值(亿) | 基础信息 |
| 涨停日 / 涨停距今(日) | 条件 2 |
| 缺口日 / 缺口幅度% / 缺口距今(日) / 缺口区间 | 条件 3 |
| 今日集中度 / 昨日集中度 / 集中度变化 | 条件 4 |
| 缺口上方K线数 | 恒为 2，便于人工核对信号时点 |
| 成本P5 / 成本P95 | 筹码分布的两个分位价，便于人工核对 |

### 自检

```bash
cd pc
python selftest.py
```

不需要联网，用构造的 K 线跑 19 个用例：正样本（四条全中）、股价 3/25 边界、
连板剔除、**涨停 1 日前 / 2 日前 / 3 日前三种时效**（只有 2 日前通过）、
缺口在涨停当日应淘汰、缺口在次日应通过、缺口已回补、幅度不足，
集中度上升剔除 / 收敛通过，以及筹码分布本身的单调性检查。

### 打包 exe

双击 `build_pc.bat`，或在 `pc/` 下执行 `python build_exe.py`。
单文件 exe 输出到桌面，文件名形如 `涨停缺口选股_20261105_153000.exe`。

## 五、Android 版

**环境**：JDK 17、Android SDK（platform 34）、Gradle 8.7。

双击 `build_android.bat`，脚本自动探测 JDK / SDK / Gradle，构建产物在
`android/app/build/outputs/apk/debug/app-debug.apk`，并复制一份到 `release/limitup-gap.apk`。
也可直接用 Android Studio 打开 `android/` 目录。

**包名**：`com.example.limitupgap`。它与「股票筛选」（`com.example.stockscreen`）、
「缺口放量选股」（`com.example.gapscreen`）都不同，**三个 App 可以同时装在一台手机上，互不覆盖**。
改包名只需动 `android/app/build.gradle.kts` 里的 `applicationId`，
`namespace` 与 Kotlin 包路径保持 `com.example.stockscreen` 不变。

**特点**：
- 筛选跑在前台 Service，点开始后可退出应用，完成后通知栏提醒；
- 4 线程并发，全量约 3~4 分钟（手机 CPU 上筹码迭代是主要耗时）；
- 界面原生 WebView，条件漏斗、命中列表与 PC 版输出一致。

> **两端算法一致性已验证**：把 `StockScreen.kt` 里的筹码计算原样抽出来，
> 用 PC 端同一份 K 线跑 7 只股票，与 `screen.py` 的结果**逐位相同**
> （最大误差 1e-13，纯浮点噪声）。筹码模型的 Kotlin 移植不存在口径漂移。

## 六、可调参数

集中在 `pc/screen.py` 顶部：

| 参数 | 默认 | 含义 |
|------|------|------|
| `PRICE_MIN` / `PRICE_MAX` | 3 / 25 | 股价区间（严格不含边界） |
| `LIMIT_UP_PCT` | 0.098 | 涨停判定阈值 |
| `BARS_ABOVE_GAP` | 2 | 缺口上方（含缺口当根）的 K 线根数，决定进场时点 |
| `NO_CONSECUTIVE` | True | 是否剔除连板 |
| `GAP_MIN_PCT` | 0.2 | 缺口幅度下限 % |
| `GAP_ALLOW_PARTIAL` | False | 是否允许部分回补 |
| `CYQ_WINDOW` | 90 | 筹码迭代窗口（交易日） |
| `CYQ_BINS` | 120 | 价格网格档数 |
| `CYQ_DECAY` | 1.0 | 筹码衰减强度（越小越"粘"） |
| `SCR_SHRINK` | True | True=要求收敛，False=要求发散 |

## 七、已知限制

- **不复权价**。K 线接口返回不复权价，缺口判定用真实价格是对的，
  但除权除息日的涨跌幅会失真，可能误判涨停。
- **筹码模型是近似**。三角形分布 + 换手衰减是业界常见的简化，
  与通达信 / 同花顺的 CYQ 不会逐位一致。它衡量的是「筹码的相对宽窄变化」，
  用来做「今天是否比昨天更集中」这种比较是可靠的，绝对值仅供参考。
- **流通股本用当前快照推算**，回溯历史日期时存在前视偏差。
- **涨停按涨幅 ≥ 9.8% 近似**，未区分新股上市首日、复牌等特殊涨跌幅情形。
- 依赖第三方公开接口，接口变更或限流会导致失败；已内置 3 次重试与请求间隔。

## 八、数据接口

| 用途 | 接口 |
|------|------|
| 股票列表 + 流通市值 | `vip.stock.finance.sina.com.cn/.../Market_Center.getHQNodeData`（`node=hs_a`，每页 100） |
| 市场总数 | `.../Market_Center.getHQNodeStockCount` |
| 日 K 线（OHLCV） | `quotes.sina.cn/cn/api/json_v2.php/CN_MarketData.getKLineData`（`scale=240`） |

列表接口需带 `Referer: https://finance.sina.com.cn`；K 线接口只需 `User-Agent`。
`nmc` 字段单位为万元，K 线 `volume` 单位为股。
