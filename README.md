# 沪深主板「缺口 + 放量 + MACD 低位」选股器

在旧版（`股票筛选2`，均线二次金叉条件）基础上按新条件重写的独立项目。
提供 **PC 命令行版（Python，零第三方依赖）** 与 **Android 后台版（Kotlin）**，
两端判定口径完全一致，支持指定任意历史基准日期回溯。

> 数据源：新浪财经公开行情接口。本项目只做数据筛选，**不构成任何投资建议**。

## 一、筛选条件

| # | 条件 | 判定口径 |
|---|------|----------|
| 0 | 市场 | 沪深主板 —— 沪市 `600/601/603/605`，深市 `000/001/002`；剔除 ST、\*ST、退 |
| 1 | 涨幅 | 当日涨幅 2% ~ 5%（含边界） |
| 2 | 成交量 | 当日量 > 5 日均量，且 ≤ 5 日均量的 2 倍 |
| 3 | 换手率 | 5% ~ 10%（含边界） |
| 4 | 流通市值 | 50 亿 ~ 200 亿 |
| 5 | 缺口 | 2 个交易日前已出现**向上跳空缺口**，且至今**未回补** |
| 6 | MACD | DIF 在零轴附近或下方；**绿柱缩短** 或 **当日刚金叉**；排除零轴上方高位金叉 |

**五条信号条件全部满足**才算命中（市场与市值属前置过滤）。

> 已按要求移除「10 日内有涨停」条件；缺口时效由「3 日前」放宽为「2 日前」。

### 几个口径的具体定义

**5 日均量**：含当日的前 5 根 K 线算术平均，即通达信 `MA(V,5)`。
因此「量比 1~2 倍」实际等价于「高于前 4 日均量、且不超过前 4 日均量的 2.67 倍」。

**向上跳空缺口**：当日最低价 > 前一日最高价，缺口区间 = `[前一日最高价, 当日最低价]`。

**未回补**：缺口出现之后（不含缺口当日）所有 K 线的最低价都没进入该区间。
即便只是盘中刺到缺口上沿，也算已回补 —— 这是最严格的口径。
改用 `--loose` 或把 `GAP_ALLOW_PARTIAL` 设为 `True` 可放宽为「允许部分回补」。

**缺口时效**：缺口距基准日至少 2 个交易日，且在最近 60 个交易日内
（原条件只说「2 日前已有」，没有上限，这里按近 60 日近似）。
同时要求缺口幅度 ≥ 0.2%（`GAP_MIN_PCT`）过滤噪声。

**MACD**：标准 12 / 26 / 9 参数，`MACD 柱 = 2 × (DIF − DEA)`（通达信口径）。
- 「零轴附近或下方」= `DIF ≤ 收盘价 × 1%`（`DIF_ZERO_BAND_PCT`）。这一条同时排除了零轴上方的高位金叉。
- 「绿柱缩短」= MACD 柱为负，但比前一日收缩（向零轴靠近）。
- 「刚金叉」= MACD 柱当日由 ≤0 转为 >0。

**换手率**：流通股本 = 流通市值 ÷ 最新价（同一时点快照），换手率 = 当日成交量 ÷ 流通股本 × 100%。

## 二、先说结论：这组条件仍然偏严

去掉涨停、把缺口放宽到 2 日后，命中数有所改善，但整体依然偏少。
用 2026 年 10 月的 10 个交易日回测（每个交易日全市场 5577 只 → 初筛约 1190 只）：

| 模式 | 10 日命中 | 日均 |
|------|-----------|------|
| 标准（默认） | 1 只 | 0.1 只 |
| `--loose` 宽松模式 | 12 只 | 1.2 只 |

单个交易日的漏斗长这样（2026-11-03）：

```
----------------------------------------------------------
筛选漏斗（候选 1192 只，可计算 1189 只）
----------------------------------------------------------
  [OK] 当日涨幅 2%~5%                  135 只  11.4%  ###......................
  [OK] 换手率 5%~10%                    7 只   0.6%  .........................
  [OK] 成交量 1~2 倍 5 日均量               6 只   0.5%  .........................
  [--] 2 日前缺口且未回补                    0 只   0.0%  .........................
  [--] MACD 低位：绿柱缩短 / 刚金叉            0 只   0.0%  .........................
----------------------------------------------------------
  五条全部满足：0 只
```

**瓶颈不在涨停，在「缺口 × 换手率」的交集**。缺口条件单独看通过率只有 2~3%
（1189 只里约 30 只有效缺口），换手率 5~10% 只有 5~8%，
两者乘起来、再乘涨幅 11%，每天就只剩个位数候选，最后能过 MACD 的自然寥寥。

还有一个结构性矛盾值得记一下：**「缺口未回补」和「MACD 在零轴附近或下方」天然互相拉扯**。
能留下未回补缺口的股票，通常正处于短期强势，DIF 早就跑到零轴上方 2~3%，
正好被 MACD 条件挡掉；反过来 MACD 在低位的股票，往往还没走出缺口。
所以要更多结果，优先动缺口和换手率，不是 MACD。

### 想多出结果，按这个顺序松

| 手段 | 做法 | 实测效果 |
|------|------|----------|
| 一键放宽（推荐先试） | `python screen.py --loose` | 日均 0.1 → **1.2 只** |
| 换手率 | 改 `TURNOVER_MIN/MAX = 3.0/15.0` | 换手通过率 6% → 15% 左右 |
| 缺口 | 改 `GAP_ALLOW_PARTIAL = True` | 由「完全未回补」放宽为「允许部分回补」 |
| 涨幅 | 改 `CHG_MIN/CHG_MAX = 0.01/0.06` | 涨幅通过率 11% → 25% 左右 |
| MACD | 改 `DIF_ZERO_BAND_PCT = 0.03` | 效果有限，DIF 本身不是瓶颈 |

`--loose` 就是前三行里的换手率 + 缺口两项预设，运行时会在第一行打印它改了什么。

**即使 0 命中，程序也会输出「观察池」**：满足 4/5 条、只差一条的个股，并标注差的是哪一条。
标准模式下每天大约 3~18 只在观察池里，0 命中的日子也有东西可看。

## 四、PC 版

**环境**：Python 3.8+，无需安装任何第三方库。

```bash
cd pc
python screen.py                    # 交互式输入日期，回车=最近交易日
python screen.py 2026-11-03         # 直接指定基准日
python screen.py --loose            # 宽松模式（日均命中约 1.2 只）
python screen.py --workers 8        # 提高并发（默认 6，太快容易被限流）
python screen.py --limit 100        # 只算前 100 只，调试用
python screen.py --pool 5           # 观察池门槛改为 5/5（等于只看命中）
```

一个交易日全量约 **60~70 秒**（1192 只候选，6 线程）。

**输出**：`output/` 目录下两个 CSV，UTF-8 BOM，Excel 双击不乱码：

- `命中_<基准日>_<时间戳>.csv` —— 五条全满足
- `观察池_<基准日>_<时间戳>.csv` —— 满足 N/5 条，附「满足条数」「未满足条件」两列

主要字段：代码、名称、基准日期、收盘价、当日涨幅%、换手率%、流通市值、量比、
成交量、5日均量、缺口日、缺口幅度%、缺口天数、缺口区间、MACD形态、DIF、DEA、MACD柱。

### 自检

```bash
cd pc
python selftest.py
```

不需要联网，用构造的 K 线跑 15 个用例，覆盖正样本（五条全中）和每条条件的边界：
涨幅 2.0% / 5.0% 恰好取到边界、量比 0.90 / 2.14 倍、缺口 0.10% 噪声 / 已回补 / 1 日前 / 2 日前、
单边上涨的高位 MACD 等。

### 打包 exe

双击 `build_pc.bat`，或在 `pc/` 下执行 `python build_exe.py`。
单文件 exe 输出到桌面，文件名形如 `缺口放量选股_20261104_130500.exe`。

## 五、Android 版

**环境**：JDK 17、Android SDK（platform 34）、Gradle 8.7。

双击 `build_android.bat`，脚本自动探测：
JDK（`JAVA_HOME` → `%LOCALAPPDATA%\jdk*` → `Program Files\Java` → `Eclipse Adoptium` → `D:\Java`）、
SDK（`ANDROID_HOME` → `ANDROID_SDK_ROOT` → `%LOCALAPPDATA%\Android\Sdk` → `D:\Android\Sdk`）、
Gradle（`GRADLE_HOME` → `%USERPROFILE%\gradle-8.7` → `C:\Gradle\gradle-*` → `PATH`）。
构建产物在 `android/app/build/outputs/apk/debug/app-debug.apk`，同时复制一份到 `release/`。

也可用 Android Studio 直接打开 `android/` 目录。

**特点**：
- 筛选跑在前台 Service，点开始后可退出应用，完成后通知栏提醒；
- 4 线程并发拉取，速度接近 PC 版；
- 界面原生 WebView，结果页除了命中列表，还会画出**条件漏斗**（每条条件剩多少只），
  0 命中时能一眼看出卡在哪一条。

> Android 版参数写在 `StockScreen.kt` 顶部的常量区，与 `screen.py` 一一对应。
> 手机上暂未提供 `--loose` 开关，需要放宽时改常量重新构建。

## 六、与旧项目（股票筛选2）的差异

| 项目 | 旧版 | 新版 |
|------|------|------|
| 信号逻辑 | MA5 二次上穿 MA10 + MACD 金叉 | 涨幅/量能/换手/市值/缺口/MACD 五条联合 |
| MACD 参数 | 6 / 13 / 5 | **12 / 26 / 9**（标准，便于判断零轴位置） |
| 数据字段 | 只用收盘价 | 完整 OHLCV（缺口需要高低价，换手率需要成交量） |
| 并发 | 单线程 0.3s/只 | 6 线程（Android 4 线程） |
| 输出 | 单张命中表 | 命中表 + 观察池 + 终端漏斗 |
| 盘中运行 | 会把当日未完成 K 线算进去 | 15:05 前自动剔除当日 K 线 |
| 边界判定 | 无容差，恰好 5.00% 可能被误杀 | 加 1e-9 容差 |
| 自检 | 无 | `selftest.py` 15 个离线用例 |

## 七、已知限制

- **流通市值是当前值**。列表接口只给当前流通市值，回溯历史日期时无法还原基准日的市值，
  因此历史筛选的市值/换手率条件实际按「今天的流通股本」计算。代码中已注明。
- **不复权价**。K 线接口返回不复权价格，缺口判定用的正是真实价格（这是对的），
  但除权除息日的涨跌幅会失真，可能误判涨幅。
- **MACD 的 EMA 以首根收盘价为种子**，与部分行情软件的 SMA 初始化会有微小差异。
- **换手率的流通股本来自快照推算**，若期间有送转股会不准确。
- 依赖第三方公开接口，接口变更或限流会导致失败；已内置 3 次重试和请求间隔。

## 八、数据接口

| 用途 | 接口 |
|------|------|
| 股票列表 + 流通市值 | `vip.stock.finance.sina.com.cn/quotes_service/api/json_v2.php/Market_Center.getHQNodeData`（`node=hs_a`，每页 100） |
| 市场总数 | `.../Market_Center.getHQNodeStockCount` |
| 日 K 线（OHLCV） | `quotes.sina.cn/cn/api/json_v2.php/CN_MarketData.getKLineData`（`scale=240`，`datalen` ≤ 500） |

列表接口需带 `Referer: https://finance.sina.com.cn`；K 线接口只需 `User-Agent`。
`nmc` 字段单位为万元，K 线 `volume` 单位为股。
